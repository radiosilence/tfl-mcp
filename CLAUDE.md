# tfl-mcp

An MCP and GraphQL server over the Transport for London Unified API, built as the `tfl` binary. `crates/tfl-api-client` is generated from TfL's OpenAPI spec by `cargo xtask regen` and never edited by hand; `crates/tfl-mcp` is the server. It ships as a container image (`ghcr.io/radiosilence/tfl-mcp`), which jaritanet deploys behind mcp-gateway by tracking this repository's releases, and as signed binaries on each GitHub release.

## Git

- Work in PRs; never push to main. PRs are squashed; merge main into a branch rather than rebasing.
- Never push tags. CI tags and publishes when a release PR merges.
- Commits are signed.

## Changelog

`CHANGELOG.md` is generated by `scripts/changelog.py` and never edited by hand. Every change adds one fragment under `changelog.d/unreleased/<section>/`, named `<pr>-<slug>.md` and holding one `- **Lead.** Detail.` entry; to correct a note, edit its fragment. `just changelog --stdout` previews the result. The format is in `changelog.d/README.md`.

## Releasing

`just release patch|minor|major` (or an exact `X.Y.Z`) branches from main, bumps `crates/tfl-mcp/Cargo.toml` and `Cargo.lock`, turns the unreleased fragments into the version and opens the release PR. Merging it is the release: CI pushes the `vX.Y.Z`, `vX.Y`, `vX` and `latest` image tags, then creates the GitHub release with the binaries and the changelog section as notes. The image goes first because jaritanet pins `vX.Y.Z` as soon as the release exists. A push releases only when it changes the version; `gh workflow run ci.yml` on main retries a release that failed part way.
